# デプロイ用リポジトリの雛形

運用者が、自分のデプロイ用リポジトリを作るときの雛形です（[ADR-0009](../../docs/decisions/0009-リポジトリの分離.md)）。このディレクトリの中身をコピーして、**非公開のリポジトリ**を作ります。

## 使い方

1. 非公開のリポジトリを作る（例：`funadansu-deploy-<運用者>`）
2. このディレクトリの中身を、そのリポジトリの直下にコピーする（`README.md` は、運用者の手順のメモに書き換える）
3. `.sops.yaml` の `age1…` の値を、運用者の公開鍵に置き換える。本番の宛先（Cloud KMS）は、鍵を作ってから足す
4. `Pulumi.dev.example.yaml` を `Pulumi.dev.yaml` にし、値を埋める
5. `ids.example.md` を `ids.md` にし、ID を記録する（**ID はこのリポジトリにだけ書く**）
6. `secrets/dev.yaml` を、`sops` で暗号化したまま作る。平文のファイルをコミットしない
7. 本体（`funadansu`）を、固定の版（タグかコミット）で参照する

## 置くもの、置かないもの

| 置く（非公開のデプロイ用リポジトリ） | 置かない（公開の本体） |
| --- | --- |
| スタックの設定（`Pulumi.<stack>.yaml`） | 特定の環境の値（ID、ドメイン） |
| sops で暗号化した秘密情報（`secrets/`） | 暗号化した秘密情報 |
| `.sops.yaml`（運用者の公開鍵） | 運用者の公開鍵 |
| 各種の ID（`ids.md`） | 本番の鍵、トークン |

## 本体の版を上げる

デプロイ用リポジトリで、本体の版（タグかコミット）を上げ、`pulumi preview` で差分を確かめてから反映します。手順は本体の `docs/operations/` に、手順を書きます（作成中）。

## 注意

- この雛形の値（`age1…`、`example.com`、ID の欄）は、すべて見本です。実在の値に置き換えてから使います
- 鍵や資格情報を、このリポジトリに平文で置かない
