# 脅威モデル

Funadansu が守るもの、入口、信頼の境界、想定する脅威と対策を書きます。方針は [ADR 0007](../decisions/0007-セキュリティの設計方針.md) です。

- 単位の移行を終えるときに、その単位の節を書きます（または更新します）
- **未修正の脆弱性の詳細は、ここに書きません**。修正版が公開された後に、必要な範囲で追記します

## 守るもの

| 守るもの | 置き場所 | 失われたときの影響 |
| --- | --- | --- |
| 利用者の個人データ（データ通帳の中身、本人確認の結果） | PostgreSQL（旧スキーマ） | 漏えい、改ざん |
| パスワードのハッシュ | PostgreSQL（旧スキーマ） | なりすまし |
| JWT の署名の鍵 | sops の正本から配る | すべてのなりすまし |
| 更新トークン | PostgreSQL の別スキーマ（ハッシュで保存） | 長期のなりすまし |
| `sid` の失効リスト（旧 API の窓口の例外を採る場合） | Workers KV など | 失効させたはずのトークンが使える |
| 運用者の管理者アカウント | 運用者の環境 | 全体の乗っ取り |

## 入口と信頼の境界

```
利用者・運用者のアプリ
  │  (1) インターネット
  ▼
proxy（Hono：Cloudflare Workers または Bun）   … JWT の検査、OpenAPI に照らした入力の検査、量の制限
  │  (2) 内部の通信（JWT をそのまま渡す）
  ▼
サービス（Go、1本のバイナリ）                  … JWT の署名の再検査、権限の確認、値の検査
  │    単位の間は関数呼び出し（「外に出す関数の一覧」を通す）
  │  (3) DB の接続（単位ごとに、元の実装のその単位の DB だけ）
  ▼
PostgreSQL（フェーズ1・2は元の実装のサービスごとの別 DB、15個）

移行期間のみ：
元の実装のサービス ──(4) セッション確認の問い合わせ──▶ operator の単位（アダプター）
```

| 境界 | 信頼しないもの | 対策 |
| --- | --- | --- |
| (1) | リクエストのすべて（ヘッダー、本文、トークン） | TLS、JWT の署名の検査（方式は固定）、入力の検査、量の制限 |
| (2) | proxy を通らずに届くリクエスト、経路そのもの | **サービスでも JWT の署名を検査する**（経路を信頼の根拠にしない）。加えて経路を制限する：Cloud Run の ingress、VPS では localhost で待ち受け |
| (3) | 他の単位 | 単位ごとに自分の DB への接続だけを持つ。接続のプールは単位ごとに小さな上限 |
| (4) | 元の実装のサービスからの問い合わせ | 受け取ったトークンを JWT として検査し、元の実装と同じ形の操作者の情報を返す。**一時的な窓口**：元の実装のサービスが残っていない状態になったら撤去する（差分台帳 D-001） |

## 想定する脅威（全体）

| 脅威 | 対策 | 状態 |
| --- | --- | --- |
| JWT の偽造（`alg` の取り違え、`none`） | 署名方式をサーバー側で固定 | 方針決定 |
| 盗まれたトークンの長期使用 | 短い有効期間、更新トークンの1回限りの使用と無効化 | 方針決定 |
| 旧 API の窓口の長命の JWT が盗まれる | 旧 API の窓口に限った例外とし、`sid` の失効リストで止める。新しい API には持ち込まない | 検討中（元の実装のクライアントの確認待ち） |
| proxy を迂回したサービスへの直接の呼び出し | サービスでも JWT を検査、経路の制限 | 方針決定 |
| アダプター（境界 4）の悪用・残り続けること | JWT の検査、撤去の条件を差分台帳に明記、撤去を移行の完了の条件に含める | 方針決定 |
| 単位をまたいだデータの読み取り | 単位ごとの DB の接続、単位の間は関数の一覧を通す | 方針決定 |
| 入力の解析の不備 | 入口と各サービスでの検査、パーサーの fuzzing | 方針決定 |
| SQL インジェクション | sqlc による型付きのクエリ（文字列の組み立てをしない） | 方針決定 |
| ログからの個人データの漏えい | ログに個人データと秘密情報を出さない規約 | P0-3 で規約化 |
| 遅いクライアントによる資源の占有 | `http.Server` のタイムアウト（`ReadHeaderTimeout` など）を必ず設定 | P0-3 で規約化 |
| 依存パッケージの脆弱性・乗っ取り | 依存を少なく、固定、govulncheck、Renovate | P0-7 |
| CI の乗っ取り | Actions の SHA 固定、最小権限 | P0-7 |
| 配布物のすり替え | 再現可能なビルド、署名、SBOM | フェーズ1まで |
