# 意思決定の記録（ADR）

このディレクトリには、Funadansu の設計上の決定を、1つの決定につき1ファイルで残します。
「何を決めたか」「なぜ決めたか」「何が起きるか」を、後から読む人が追えるようにするためのものです。

差分台帳（[docs/spec-deviations.md](../spec-deviations.md)）は、仕様と元の実装との違いを記録する場所です。ADR は、違いの有無にかかわらず、設計の決定そのものを記録します。

## いつ書くか

- 後で覆すと影響が大きい決定（認証、データの持ち方、互換の方針など）
- 同じ議論が繰り返されそうな決定
- 決定の理由を残しておきたいとき

## 置き方

- 番号は `0001` から連番にします。ファイル名は `NNNN-題名.md`（例：`0001-題名.md`）
- 新しく書くときは [_template.md](_template.md) を写して使います
- 1ファイルに1つの決定だけを書きます
- 書式は日本語で、短く書きます。評価の言葉ではなく、何を決めたか、なぜか、何が起きるかを書きます

### 状態

| 状態 | 意味 |
| --- | --- |
| proposed | 提案中。まだ採用していない |
| accepted | 採用した |
| superseded | 後の ADR に置き換えた。置き換え先の番号を書く |

決定を変えるときは、古い ADR を消さず、状態を `superseded` にして、新しい ADR の番号を書きます。

## 候補

- フェーズ1の認証（[docs/migration-phases.md](../migration-phases.md) の「フェーズ1の認証」）は、最初の ADR の候補です。まだ ADR は作っていません。
