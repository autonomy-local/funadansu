## 確認の途中で分かったこと

- catalog-update の試験は、スタブを立てる試験と、立てない試験が同じファイルにあります。スタブを使う試験は E2E に入れず、単体テストへ回しました（09-01 の 19 件）
- 旧 OpenAPI の試験の一部は、応答の本文を見ていません（仕様どおり、ステータスだけを見る）。シナリオは、試験が見ている項目だけを確かめます。記録の本文（既定の `{}` や、実行時刻の `applicantDate`）を全部比べると、試験より厳しくなるため
- 試験は DB の状態を持ち越します（各ファイルの前に表を空にしないと、結果が変わります）。E2E の各シナリオは、最初に表を空にしてから、試験の DB 準備を流します
- 公開カタログ（`/catalog/public`）の試験は、DB の表を空にしたあと、試験の SQL で行を入れてから GREEN になります
