# 運用の手引き

Funadansu を運用する人（運用者）向けの手引きです。

## はじめに：担保できる範囲

Funadansu は、運用者が自ら運用することを前提にしています（Do It Yourself の原則）。開発者は運用者のサーバーに手が届かないため、運用時の安全は**できうる限り**の担保にとどまります。

| 開発者が行うこと | 運用者に行っていただくこと |
| --- | --- |
| 設計の時点で脆弱性をなくす（[ADR 0007](../decisions/0007-セキュリティの設計方針.md)） | サーバーとアカウントの管理 |
| 安全な初期値（NixOS のモジュール） | 初期値を緩めるときの判断と記録 |
| この手引き | 手引きに沿った構築・更新・バックアップ |
| 脆弱性の修正版と告知 | 告知を受けたら速やかに更新する |

運用の責任は運用者にあります。

## 手引きの一覧

構成は Pulumi（Cloud Run・Cloudflare Workers）と NixOS（VPS）で記述します。初版はフェーズ0で、dev の環境を立てるのと一緒に書きます。

| 文書 | 内容 | 状態 |
| --- | --- | --- |
| deploy.md | 最小のデプロイ：ローカルで CI（GitHub Actions と同じ `nix flake check` など）を通してから、`pulumi up`（Cloud Run・Workers）と `nixos-rebuild switch --target-host`（VPS）で反映する。切り戻しの手順 | 未着手 |
| hardening.md | VPS（NixOS）の固め方：ファイアウォール、TLS、SSH、自動更新、ログの保存先 | 未着手 |
| backup-restore.md | バックアップと復元：事業者の外への書き換えられないバックアップ、復元の訓練 | 未着手 |
| secrets.md | 鍵の管理：sops と age の鍵、JWT の鍵の交換、漏えい時の入れ替え | 未着手 |
| upgrade.md | 更新の手順：リリースの署名の確かめ方、切り戻し | 未着手 |
| incident.md | 事故のとき：初動（止める・保全・連絡）、関係機関への報告、利用者への告知 | 未着手 |

## 脆弱性の告知を受け取る

- [ADOPTERS.md](../../ADOPTERS.md) に登録された連絡先に、脆弱性の告知を直接送ります。連絡先は最新に保ってください
- あわせて、GitHub Security Advisories とリリースのタグでも告知します
- 脆弱性を見つけた場合は、公開の場に書かずに [SECURITY.md](../../SECURITY.md) の窓口へ報告してください

## 運用者同士の協力

事故の情報や手順を共有する場を用意します（方式は運用者が増えた段階で決めます）。
